# 项目重构方案（按清晰需求版本）

## 1. 项目目标

本项目需要做成一个单工作簿的 Excel + VBA 进销存管理系统，核心目标是：

- 统一维护基础信息：商品、供应商、客户
- 所有单据中的商品、供应商、客户只能从基础信息中下拉选择，不能手工录入
- 单位在选择商品后自动带出，并保持一致
- 入库、销售、退货、报损、报溢等单据录入后自动保存明细并清空表单
- 库存统计自动更新，且按要求计算成本均价和库存数量
- 利润统计自动汇总销售单和销售退货单，并在保存时冻结单价与成本均价
- 若基础信息修改，相关表单和汇总应跟随更新
- 以 Excel 表格和 VBA 宏为核心，不依赖额外数据库

## 3. 需求修正后的业务规则

### 3.1 基础信息规则

- 商品名称、供应商名称、客户名称必须从基础信息中选择
- 不能直接手工填写
- 重复录入时提示并禁止保存
- 商品名称确定后，单位自动带出
- 若基础信息被修改，所有相关表格中的名称和显示字段应同步更新

### 3.2 单据录入规则

- 入库单：供货单位、日期、商品名称、数量等必须满足字段要求
- 销售单：客户、商品、数量、单价、金额等必须完整
- 销售退货单：客户、商品、数量、退货单价、金额等必须完整
- 进货退货单：供应商、商品、数量、退货单价、金额等必须完整
- 报损和报溢单：不需要单价和金额字段
- 同一商品在不同客户下可有不同销售单价，不能笼统按商品唯一价格处理

### 3.3 库存规则

库存数量公式：

库存数量 = 入库数量 - 销售数量 + 销售退货数量 - 进货退货数量 + 报溢数量 - 报损数量

成本均价规则：

- 进货时：
  成本均价 = （现有库存总价 + 本次进货总价）÷（现有库存数量 + 进货数量）
- 进货退货时：
  成本均价 = （现有库存总价 - 退货总金额）÷（现有库存数量 - 退货数量）

库存统计应自动更新：
- 商品名称
- 单位
- 库存数量
- 成本均价
- 库存总价

### 3.4 利润规则

利润统计只统计：
- 销售单
- 销售退货单

利润公式：

利润 = 数量 × （销售单价 - 成本均价） + 调整

其中：
- 调整项允许手工录入
- 默认值为 0
- 销售单价和成本均价一旦保存，不再改变
- 保存时即形成历史快照，后续基础资料修改不影响历史利润

## 4. 关键技术设计

### 4.1 基础信息与下拉联动

- 商品、供应商、客户均从基础信息表读取
- 单据页使用 Data Validation + VBA 动态刷新下拉列表
- 选择商品后自动填充单位
- 列表中不允许重复名称

### 4.2 统一保存逻辑

对每种单据使用统一模式：

1. 校验必填字段
2. 校验数值是否合法
3. 检查商品/供应商/客户是否存在
4. 自动计算金额或成本
5. 写入明细表
6. 清空录入区
7. 触发库存和利润更新

### 4.3 库存与利润同步

- 每次保存成功后，调用库存重算函数
- 销售/销售退货保存时，写入利润快照表
- 利润统计表作为历史数据，不做实时重算

### 4.4 基础信息变更同步

如果基础信息被修改：

- 相关表格下拉列表应刷新
- 相关名称显示应同步更新
- 历史明细记录保留原始值，不被错误覆盖

此处需要使用：
- WorkSheet_Change 事件
- 中心化的名称查询和刷新函数

## 5. VBA 模块拆分（建议）

建议按照以下模块重构，而不是继续堆在单个主模块中：

- modBaseData
  - 基础信息维护
  - 去重校验
  - 下拉列表刷新
- modValidation
  - 必填校验
  - 数值校验
  - 选项限制校验
- modTransactionEntry
  - 入库、销售、退货、报损、报溢的保存逻辑
  - 清空录入区
- modInventoryCalc
  - 库存统计重算
  - 成本均价计算
- modProfitCalc
  - 利润快照生成
  - 销售退货利润处理
- modWorkbookEvents
  - 工作表变更事件
  - 基础信息同步事件
- modUI
  - 保存、清空、关闭、刷新按钮绑定

## 6. 验证范围（必须完成）

### 6.1 基础资料验证

- 反复测试重复名称
- 验证商品名称下拉唯一
- 验证供应商、客户下拉唯一

### 6.2 入库/销售/退货验证

- 录入入库单
- 录入销售单
- 录入销售退货单
- 录入进货退货单
- 录入报损单
- 录入报溢单
- 验证数据写入明细表并能清空录入区

### 6.3 库存验证

- 核对库存数量公式
- 核对成本均价公式
- 验证库存统计是否自动更新

### 6.4 利润验证

- 销售保存后，观察利润统计是否记入当时单价和成本均价
- 修改基础信息后，验证历史利润不受影响

### 6.5 同步验证

- 修改基础信息中的商品/客户/供应商名称后，单据中的对应字段应保持同步
- 历史数据保持稳定，不被错误重算覆盖

## 7. 当前实施判断

当前已存在的实现文件：

- InventorySystem.bas
- InventorySystem_Complete.bas

其结构已经较接近本需求的基础版本，但还有两处需要重点重构：

1. 基础信息修改后的联动同步逻辑仍需提升
2. 模块职责需要按 modBaseData / modValidation / modInventoryCalc / modProfitCalc 等进一步拆分

也就是说：
- 当前版本可作为技术基线
- 但需要按照“清晰需求”重新组织开发范围和实现顺序

---

## 8. 实施顺序建议

建议按下面顺序完成：

1. 先建立工作簿结构和基础信息表
2. 再完成下拉、去重和单位自动带出
3. 再完成入库/销售/退货单的保存逻辑
4. 接着完成库存统计重算
5. 然后完成利润快照和历史冻结
6. 最后补充基础信息修改后的同步和界面美化

---

## 9. 结论

该项目的清晰需求最终可以落地为：

- 单工作簿，多单据，多汇总
- 商品/供应商/客户必须来自基础数据
- 库存和利润必须自动计算
- 利润必须保留历史快照
- 基础信息变化须同步更新相关显示

这才是符合本说明的最终版本。
